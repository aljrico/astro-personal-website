Committed the first version of the durable coordinator. A Haiku 5.5 coordinator hands each coding task to a fresh Opus 5.5 worker through the Agent SDK, with state in SQLite. Then I went through my own review notes. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

The system prompt changed on every reopen, so nothing could cache and the runs file grew without limit. Now the system prompt is static, and each reopened or fresh session gets a one-shot project_state briefing. Run records keep what the user typed, not the briefing. Boring plumbing. It's the kind that decides what this costs.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now delegate_coding and record_decision are gated through canUseTool and off the allowed list. It can't disobey. That feels better than hoping.

Decisions got IDs and a supersedes field. Both migrations go through Pi Durable's migrate, and a test that runs real v1 data through it proves the path. Not glamorous. Necessary.

Pi Durable runs one process per storage with no cross-process locking, so status reads a state.json mirror while the lock is held. The CLI end-to-end test runs in a temp home.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The write prompt shows the first 30 lines, but Bash output never gets clipped. Control and bidi characters get escaped before printing, because a right-to-left override can make a line read differently from what it does. JSON.stringify misses that one. Gotcha of the day: the tool pipeline turned my \u escapes into literal bidi characters in the source. Fixed by building them from char codes.

Late in the day, the plan-limit work. A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake. A rate-limit event now pauses the run, and chat refuses sends until the reset time. The CLI works out from the status fields whether extra usage is in play, then aborts the shared controller with a plan-limit reason. Sibling streams record a plan limit instead of a generic abort.

Seven tests green. Nothing live-tested. The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
