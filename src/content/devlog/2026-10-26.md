First real commit of the durable coordinator. A Haiku coordinator, fresh Opus workers for each job, the Agent SDK underneath, state in SQLite. Before committing I reviewed it, and the review found things I'd rather find now than in a bug report.

Went through my own review notes. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now the dispatch and decision tools are gated in the permission check and removed from the allowed list. It can't disobey. That feels better than hoping.

The system prompt is static now. Each reopened or fresh session gets a one-shot project briefing instead. The prompt caches properly, and the run records stop bloating, because they store what I typed, not what the model was told.

Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary.

Pi Durable allows one process per storage and has no cross-process locking. So a status check reads a mirror file while the store is locked. Boring plumbing, but it's the kind that bites you later.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows the first 30 lines, and Bash output is never clipped. Control and bidi characters get escaped before display. The funny bit: JSON.stringify doesn't escape U+202E, and the tool pipeline had turned my \u escapes into literal bidi characters in the source. I had to build them from char codes. The file was lying to me.

Late in the day, the plan-limit work. The SDK sends a rate-limit event. If the account is rejected and extra usage is in play, the coordinator aborts everything in flight with a plan-limit reason, and sibling streams record that instead of looking like a generic abort. The run goes to paused, and chat refuses sends until the reset time.

A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake.

Seven tests green, and the plan-limit detection passes 8 of 8 on synthetic events. Very clean number for something I've never actually seen happen. Nothing live-tested.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
