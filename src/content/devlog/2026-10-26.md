Committed the durable coordinator first. Haiku coordinates, fresh Opus workers do the coding, and the state lives in SQLite. Before the commit, I found a few things that needed fixing, and the first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback. I also stopped resending the system prompt every turn and send a one-shot project briefing on each reopen instead. Cheaper, and the prompt cache finally behaves.

Then I went through my own review notes. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

I moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now it can't disobey. That feels better than hoping.

Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Status reads a mirror file now, because the storage library allows one process per store and no locking across processes. Boring, and it works. Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows the first 30 lines of a file, and Bash output is never clipped. Control and bidi characters get escaped. The tool pipeline also turned my \u escapes into real invisible bidi characters in the source, so I built them from char codes. Gotcha of the day.

Late in the day, the plan-limit work. The SDK sends a rate-limit event. If the account is over its plan and extra usage is allowed, the CLI aborts everything in flight, the run pauses, and chat refuses sends until the reset time. But in-flight requests can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake.

Seven tests green. Nothing live-tested. The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
