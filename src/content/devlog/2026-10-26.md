Committed the durable coordinator around half past seven. Haiku runs the show, fresh Opus workers do the coding through the Agent SDK, and state lives in SQLite. Then I went back through my own review notes. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first fix scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

The same pass moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now the delegate and decision tools are gated in code, and they're off the allowlist. It can't disobey. That feels better than hoping.

I also swapped the big prompt for a static system prompt plus a one-shot project briefing on each reopen. Caching works again, and the run records store what I typed, not the briefing. Small change, but the run JSON stopped growing without bound.

Then the six-item sweep, one commit each. Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary.

There's a state.json mirror now, because the storage has no cross-process locking. Status reads the copy while the lock is held. Smoke runs got their own flag instead of sharing the coordinator save path.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows the first thirty lines, but Bash output is never clipped. The printable helper escapes control and bidi characters. JSON.stringify misses U+202E, which I learned the hard way. Worse, the tool pipeline decoded my \u escapes into literal bidi characters in the source. I fixed it by building them from char codes.

Late in the day, the plan-limit work. A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake. When the status comes back rejected, the run pauses and chat refuses sends until the reset time. Aborted parallel streams record a plan limit instead of a generic abort.

Seven tests green. Nothing live-tested. The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
