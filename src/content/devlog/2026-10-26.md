Committed the first version of the durable coordinator. A Haiku 5.5 coordinator hands each coding task to a fresh Opus 5.5 worker through the Agent SDK, with state in SQLite. Then I went through my own review notes. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

The system prompt changed on every reopen, so nothing could cache and the runs file grew without limit. Now the system prompt is static, and each reopened or fresh session gets a one-shot project_state briefing. Run records keep what the user typed, not the briefing. Boring plumbing. It's the kind that decides what this costs.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now delegate_coding and record_decision are gated through canUseTool and off the allowed list. It can't disobey. That feels better than hoping.

Decisions got IDs and a supersedes field. Both migrations go through Pi Durable's migrate, and a test that runs real v1 data through it proves the path. Not glamorous. Necessary.

Pi Durable runs one process per storage with no cross-process locking, so status reads a state.json mirror while the lock is held. The CLI end-to-end test runs in a temp home.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The write prompt shows the first 30 lines, but Bash output never gets clipped. Control and bidi characters get escaped before printing, because a right-to-left override can make a line read differently from what it does. JSON.stringify misses that one. Gotcha of the day: the tool pipeline turned my \u escapes into literal bidi characters in the source. Fixed by building them from char codes.

Then I stopped and asked what this thing is for. Answer: a personal tool first. I committed the refocused vision doc and readme at 11:24, and the direction is a game builder that starts as a tool for my own mobile games. Laptop, my own subscriptions, a phone remote. Phase two is a Lovable-style builder for people who can't code. Phase one is what I can actually build now.

I researched why it has to be phase one. The Agent SDK docs still bar third-party products from offering claude.ai login. A product for other people can't run on their subscriptions. My own tool can. Then OpenAI launched "Sign in with ChatGPT" usage sharing with sixteen partners, and one of them is a company I'd been planning to compete with in phase two. Arrived at the party after the cake was gone.

I also measured the disk. Pi Durable keeps only the current docs revision, so 400 runs is about 1MB. The real hog is my Claude Code transcript folder: 3.8GB across 1368 sessions. Not the thing I'd been worried about.

Then the MVP, six steps, one commit each. My own scratch log puts all six between 11:27 and 11:52. Fast, or the log is lying. Probably both. Fake-SDK tests first. SDK calls now go through a swappable object, and a scripted model pushes tool calls through the permission check the way the real CLI does. Five coordinator tests. Thirteen passing. Boring, which is exactly what I wanted.

Rotation next. When the coordinator passes 60k tokens, the old session writes a handoff under 500 words with tools denied. A fresh session starts with those notes, the decisions, the last ten turns, and the last five workers. Two resume failures in a row now set the session aside by themselves. Goodbye, manual /new.

Then the sandbox. I swapped it ahead of background workers, because a background worker can't ask for permission while I'm typing in the terminal. Workers run with accept-edits inside Claude Code's sandbox, network allowlisted to the npm registry only, and canUseTool denies everything. The spike with Haiku: home directory writes blocked, example.com blocked by the proxy, npm reachable, /tmp allowed. canUseTool was never called. The sandbox decided before the permission callback got a vote. That's the kind of plumbing that earns trust. It also left an empty folder in the project. Noted for later.

Background workers came next. delegate_coding returns "Started" immediately, and the outcome arrives later as an event turn. Coordinator turns go through one queue. Event turns can't dispatch anything. They run with deny-all permissions, so only a message from me can start a worker. If an event turn fails, its events go back in the queue and ride along with my next message. The CLI side ate more of my patience than the feature did. readline's question needs an AbortSignal, because close() alone leaves a pending question hanging forever. Two overlapping questions deadlock the second one. Background output now clears and redraws the prompt, so it doesn't eat what I'm typing. Typing during an approval prompt gets held until it's answered. /quit asks first if a worker is still running, and shutdown waits so the final statuses get recorded. A test hung on a race in the fake worker. Added a timeout. Nineteen tests.

Each worker's changes now become one commit, whatever the outcome. Dirty trees and non-repos get refused up front. A `starting` flag claims the slot, because parallel tool calls in one message could otherwise start two workers at once. Anything over 2000 changed files gets refused too, since that usually means .gitignore is missing something. The commit is named `w1: headline`, so the history reads like a diary of what the workers did. The briefing lists uncommitted changes, so after a kill -9 mid-worker the coordinator knows the tree is dirty.

Last step: archive. The state doc was being rewritten in full on every commit and re-read every turn. Linear growth I'd never have noticed without measuring. Now the hot doc keeps the last 40 runs, and older finished runs move to append-only entries in the same commit. With 2000 simulated runs, the hot doc stays flat at 89 KB, the database sits at 8 MB, and each run costs 0.7 ms, constant. The stored prompt and result get capped at 8000 characters. Transcripts get pruned fourteen days after their worker or coordinator is retired. The current coordinator is never touched. /status now shows the state size and how many megabytes of transcripts are still kept. Twenty-four tests by the end.

First live run, at 11:54, two minutes after the last commit. In a throwaway repo, driven through expect in a pty. I approved a dispatch. A sandboxed Opus worker wrote hello.txt. The app committed it. The worker's event came back, Haiku reported it, and /status showed 0.3 MB of state and two transcripts. It worked. The whole loop, end to end, for a file that says hello. I showed it to the empty room anyway. Look at this. It wrote a file and told me about it.

It also surfaced a bug. Haiku's brief told the worker to commit to git. Then Haiku saw the app's commit and read it as a contradiction of the worker's "untracked" report. Fixed in the coordinator prompt and the event wording. The event wording was still wrong, as it turned out, and got fixed again later in the day. Also, `claude auth status` exits non-zero when you're logged out, with JSON on stdout. Now I parse it, so the friendly login hint actually shows.

After lunch I switched to a different repo, a small Flutter app, and cleared its leftovers. At 15:35 I pushed the pubspec.lock bumps (intl, matcher, meta) that the Flutter upgrade left behind. Boring files, but it felt good to close them out. The Flama analytics work from another session, a dev/prod split in the online service and its integration doc, sitting in the same tree, stayed out. It doesn't compile against the pinned SDK, the `environment` parameter it needs isn't there, and its own doc says not to ship until the pins are bumped. Not my change to rush. A probe script and some balance outputs stayed out too, never committed. Clean commit, dirty tree, and a small, quiet win.

Late in the day, the plan-limit work. The sandbox spike had already told me extra usage is switched off on this account, and the rate-limit event said so in writing: disabled at the org level. So the guard is a seatbelt for a crash that may never happen here. Still worth having. A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake. A rate-limit event now pauses the run, and chat refuses sends until the reset time. The CLI works out from the status fields whether extra usage is in play, then aborts the shared controller with a plan-limit reason. Sibling streams record a plan limit instead of a generic abort.

Plan-limit tests are green. Nothing live-tested. The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Around 16:50, one more pass before calling it done. I ran /simplify on the changes from 5f700d3 with four review agents: reuse, simplification, efficiency, and altitude. The altitude one caught something real. The worker event claimed the app had committed the changes, even when the worker had committed everything itself. In that case the app commits nothing. It just returns the worker's HEAD. I'd written that line and felt pretty pleased with it. Now the event states git facts instead: changes since the worker started, through a commit and its sha. The system prompt already says the app commits, so the story lives there. The login check also got cleaned up. It was execFileSync wrapped in a try/catch. It's now spawnSync, because a logged-out status still prints its JSON on a non-zero exit. A missing binary still throws, and empty stdout throws with stderr attached. I skipped two things. Moving the TTY check ahead of the login check is out of scope for a tiny gain. Blocking .git writes in the worker sandbox would break stash and checkout, so no. Reuse and efficiency came back clean. Types check and 24 of 24 tests pass. Committed as c42d94b.

Good day. More building than spreadsheets, though I did measure things. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
