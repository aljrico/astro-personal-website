Went through my own review notes today. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The coordinator's first commit went in that evening. Haiku 5.5 coordinates, fresh Opus 5.5 workers do the coding through the Agent SDK, and state lives in SQLite. The pre-commit review found things I'd rather catch now than later.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now delegation and decision recording go through a permission check and aren't even in the allowed tools. It can't disobey. That feels better than hoping.

The system prompt is static now, with a one-shot project state briefing on each reopen. The old version rebuilt the prompt every time, so caching was dead and the runs file grew without limit. Run records keep what the user typed, not the briefing.

Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary. Smoke runs got a flag on the run record, which replaced an old switch. That's a second migration, and it's tested the same way.

Pi Durable allows one process per storage with no cross-process locking, so status can't open the database while the coordinator holds it. Status reads a state.json mirror instead. Obvious in hindsight. I'll take it.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows the first 30 lines now, and Bash output is never clipped. A printable() helper escapes control and bidi characters. Then the gotcha: JSON.stringify doesn't escape U+202E, and the tool pipeline turned my escape sequences into literal bidi characters in the source. I fixed it by building them from char codes. Seven tests green. Nothing live-tested.

Late in the day, the plan-limit work. The SDK's rate-limit event marks the run paused, and the chat refuses sends until the reset time. The CLI decides overage from the status plus the overage flags, so I abort the shared controller with a plan-limit reason. Sibling streams that get cut off record a plan limit, not an AbortError. A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake.

The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
