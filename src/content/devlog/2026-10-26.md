Committed the durable coordinator. Haiku as the coordinator, a fresh Opus worker for each task, state in SQLite. Then I went through my own review notes before touching anything else. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now it can't disobey. That feels better than hoping. Delegation and decision recording are gated in the permission hook now, not left to the prompt.

Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary.

The system prompt is static now, with a one-shot project briefing on each reopen. Prompt caching works again, and the run records stop growing without bound. Status reads a state.json mirror, because the storage library allows one process per store and no locking across processes. Not elegant, but it works.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows the first 30 lines, and Bash output is never clipped. Escaping control and bidi characters caught a nasty one: my tool pipeline turned \u escapes into literal bidi characters in the source. I rebuilt them from char codes. Trust nothing that looks clean in a diff.

Late in the day, the plan-limit work. A rate-limit event can abort in-flight requests, but those can still get billed, because the report arrives with a response. So the real guard is turning off extra usage on the account. The code is a seatbelt, not a brake.

Seven tests green. Nothing live-tested. The limit logic passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
