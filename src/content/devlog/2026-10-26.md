First commit of the durable coordinator went in. Haiku runs the coordinator, a fresh Opus worker does each job, and the state lives in SQLite. Then I went through my own review notes. Six items, one commit each. Cleaning a desk I'd been ignoring for weeks, and it felt great.

The first one scared me. If a transcript went missing, resume would brick the session forever. Cleanup deletes after thirty days by default, so this wasn't theoretical. Joder. Fixed the fallback.

I also moved the "don't re-dispatch" rule out of the model's good manners and into code. The coordinator was obeying the instruction. Now it can't disobey. The decision-recording tool is gated in code too. That feels better than hoping.

While I was in there, the system prompt went static, with one briefing per reopen. Prompt caching works now, and the runs file stops growing without limit.

Decisions got IDs and a supersedes field. The migration for old data only counts if it runs against real v1 data, not fresh data, so I ran it against a copy of the real thing. Not glamorous. Necessary. Storage is one process with no cross-process locking, so status reads a mirror file while the lock is held. Boring plumbing, the kind nobody sees until it breaks.

The /new escape hatch exists because one CLI error repeats on every retry, and the SDK only says "invalid request". I refused to string-match error messages. Ask me again in a month.

Worker turn limit went from 30 to 100. When it hits, the session resumes for one report-only turn with every permission denied. Honestly, a neat bit of plumbing.

The Write prompt shows only the first 30 lines, but Bash output is never clipped. Escaping control and bidi characters was its own small comedy. JSON.stringify doesn't catch U+202E, and the tool pipeline turned my \u escapes into literal bidi characters in the source. I ended up building them from char codes. Seven tests green. Nothing live-tested.

Late in the day, the plan-limit work. An SDK rate-limit event now pauses the run, and chat refuses sends until the reset time. The CLI decides we're in overage and aborts everything in flight with a plan-limit reason instead of a generic abort. But the report arrives with a response, so requests already in flight can still get billed. The real guard is turning off extra usage on the account. The code is a seatbelt, not a brake.

I can't test any of this against a real limit. planLimit() passes 8 of 8 on synthetic events, which is a very clean number for something I've never actually seen happen.

Good day, the kind where I decided things and didn't write a spreadsheet about them. The background hum is still there, the one asking whether anyone will run this besides me. Probably not yet. Doesn't matter tonight.
