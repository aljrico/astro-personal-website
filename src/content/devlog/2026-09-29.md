Morning was roads. Spent weeks convinced the filled concentric outlines with radius-0.7 were the right answer — proper energy, mathematically sound. Pushed it this afternoon and the payoff landed: exact arc math, quarter circles, one stroked centreline per route. The `roundedPolyline` function replaced four helpers that were doing invisible work — `cornerRadii`, `roadOutline`, `filletPolyline`, `truncatePolyline`. All gone. Invader pathfinding now uses exact arc math instead. Road width went from roughly 0.55 to 0.45 cells.

That moment when deleting code also deletes visual noise. The roads look better. Simpler, less cluttered. Rare and good.

But the downside showed up immediately. Narrower pavement means enemy bodies and lane drift now overhang the roads. The super tank is 0.5 cells wide. Either shrink all bodies by twenty percent or walk this back. The junctions finally merge correctly on paper — haven't seen it on screen yet. Haven't decided if this is the right trade.

Afternoon caught something in the leaderboard data. An idle daily survival run somehow got posted to the real leaderboard. 0:43, real entry, real problem — the kind of anomaly that jumps out when someone actually looks at the stats. Redirected test runs to campaign levels instead. Small fix. Large weight.

Evening was monetization infrastructure. Phase 4: consent-aware post-game review, ad precedence, UMP readiness memoized, confirmed-no-fill schedule, 60-second no-stack guard. Wired the onPurchased callback into the shared ReviewEngine. 119 tests passed, 2 skipped, analyzer clean. Invisible work — the kind nobody wants to watch happen. But it has to happen.

Left some uncommitted on purpose: icon tweaks, formatter noise, sketch code. The roads are today's story.

The narrower roads are a problem I didn't anticipate. Probably shrink the tanks tomorrow. But the refactor itself feels right — cleaner code, cleaner visuals, cleaner rules. Sometimes you need the visual payoff to forgive the complications it creates.
